# 变更日志

本文档记录 ZTools 设计规范系统的所有重要变更。

格式基于 [Keep a Changelog](https://keepachangelog.com/zh-CN/1.0.0/)，
版本号遵循 [语义化版本](https://semver.org/lang/zh-CN/)。

## [1.0.0] - 2024

### 新增

- ✨ 完整的设计规范系统
- 🎨 色彩系统（亮色和暗色模式）
- 📝 字体系统（5 个标题层级 + 4 个正文层级）
- 📏 间距系统（基于 4px 网格）
- 🔲 圆角系统（6 个层级）
- 🌑 阴影系统（4 个层级，支持双主题）
- 🧩 组件库（8 个核心组件）
  - 按钮组件（Primary、Secondary、Icon、Favorite）
  - 卡片组件（Plugin Card）
  - 导航组件（Header、Sidebar、Nav Item）
  - 输入组件（Search Input）
  - 分页组件
  - Toast 提示组件
  - 进度条组件
  - 用户头像组件
- 📐 布局规范（页面结构、网格系统）
- 🎭 交互规范（动画、悬停效果、加载状态）
- 📱 响应式设计（6 个断点）
- ♿ 可访问性指南（WCAG 2.1 AA 标准）
- 📚 完整的文档系统
  - 设计规范文档
  - 需求文档
  - 实施任务清单
  - 主题切换指南
  - 快速开始指南

### 设计原则

- 一致性优先
- 简洁而强大
- 可访问性
- 性能导向
- 可扩展性

### 技术特性

- CSS 变量系统
- 主题切换机制
- 移动端优先策略
- 模块化设计
- 原子设计理论

## 贡献指南

### 如何报告问题

1. 在团队协作平台创建 Issue
2. 描述问题的详细情况
3. 提供复现步骤
4. 附上截图或代码示例

### 如何提出改进建议

1. 说明改进的目标和原因
2. 提供设计方案或代码示例
3. 考虑向下兼容性
4. 团队评审通过后实施

### 如何贡献代码

1. Fork 项目仓库
2. 创建特性分支
3. 提交变更
4. 创建 Pull Request
5. 等待团队评审
